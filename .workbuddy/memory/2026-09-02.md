### GPU 路径全部失败（决定性结论）
- default / --lowvram / --reserve-vram 6: GGUF patcher 始终 `lowvram patches: 0` 不分块 → transformer(8.53/11.53GB) 整块上 GPU, 显存撑到 15.8/16.3GB(97%) → warmup 第一步 (`0/8 [Model Initializing]`) swap thrashing 卡死 12min+。Q2_K 与 Q3_K_M 结果相同, 降分辨率(768→512)也无效(仍 15.76GB 满)。
- `--novram`: 模型常驻 CPU(显存降到 2.1GB), 但 GGUF patcher 不逐层搬权重 → **RuntimeError: Expected all tensors to be on the same device, but got mat2 is on cpu, different from other tensors on cuda:0 (wrapper_CUDA_bmm)**, Prompt executed 368s 后失败。
- 根因: city96 ComfyUI-GGUF 的 GGUFModelPatcher 与 ComfyUI-LTXVideo 的 LTXAVTEModel_ 组合不支持分块/逐层 offload。**16GB 显存跑 LTX-2.5 不可行**(印证 ltxworkflow 权威结论)。

### 纯 CPU 模式(--cpu)突破死结但无实用价值
- 权重/VAE/TE 全在 CPU(`loaded completely; 8533.69 MB loaded, full load: True`, VAE load device: cpu, TE fp8 on cpu), 采样循环启动到 `0/8` 且**无 OOM、无 device mismatch** → 证明管线与工作流本身正确。
- 但 22B 纯 CPU 推理极慢: CPU 负载约 60%, **首步 >22 分钟仍未完成**, 8 步预计 1.5–3 小时(9帧/512x288 的最小片段), 无实用价值。测试仍在后台跑。

### 结论与下一步(待用户决策)
1. 16GB GPU 跑 LTX-2.5 = 死路(GGUF patcher 不分块 → GPU 撑满/device mismatch; CPU 能跑通但太慢)。
2. 建议: ①升级 ≥24GB 显存(7900XTX/5090/4090, Q3_K_M 11.53GB 可跑, 已下权重); ②或 AMD 395(128GB UMA, ROCm+GGUF/BF16); ③或换 16GB 可跑的 GPU 模型(Wan2.2 GGUF, 质量第一梯队)。
3. 已保留资产: ComfyUI-GGUF 节点、Q2_K(8.83GB)+Q3_K_M(11.53GB) 权重、ltx_engine GGUF 替换逻辑、download_ltx25_gguf.py/download_gguf_mt.py/run_ltx_gguf_test.py。
