## 实现服务自愈（P0+P1，用户「要」）
针对「WebUI 被回收 → 打开就 Failed to fetch」的根因，落地服务自愈 + 三项小改：
- **`supervise.py`（新增）**：看护 ComfyUI(:8188)+WebUI(:8000)，进程死自动拉起，日志落绝对路径 `outputs/_webui.log` / `outputs/_comfy.log`。
  - WebUI 用 `sys.executable` 启动（跑 supervise 的 python 即 WebUI 的 venv，免去硬编码）；ComfyUI 路径固定 `D:/ComfyUI/venv/Scripts/python.exe`。
  - 启动若端口已被**健康**实例占用 → 接管监控不打断；**非健康**占用 → taskkill 回收再拉起。
  - 子进程存活但健康检查失败（假死）→ 过 60s 宽限期后重启；2 分钟内重启 >8 次 → 暂停 60s 防雪崩。
  - 所有探测 `ProxyHandler({})` 强制不走代理；子进程注入 `NO_PROXY=127.0.0.1,localhost`。
- **`start_all.bat`（新增）**：用 ai管理 venv 跑 `supervise.py` 的一键启动。
- **`webui.py` 改**：① 模块级注入 `NO_PROXY`（只补 127.0.0.1,localhost，不破坏现有代理）；② `main()` 启动前 `socket.bind` 预检端口占用 → 占用则明确报错+taskkill 提示并 `sys.exit(1)`（消灭「旧实例没退、新路由 404」陷阱）。
- **`webserver/views/anchor.py::api_anchor_run` 改**：生成前置 `comfy_ready()` 自检，未就绪直接 409+「ComfyUI 未连接」文案，避免脚本静默退出只留日志末行。

### 验证（实测）
- 旧手动 WebUI（task LY0Gmt, pid 31140）与 ComfyUI(pid 21116) 都还在 → supervise 启动后**接管监控、零打扰**（curl 8000/8188 仍 200）。
- `taskkill /PID 31140 /F` 杀掉被接管的 WebUI → 约 20s 内 supervisor 自动重拉，`:8000` 恢复 200（日志：`已强制结束 pid=31140 → 已启动 pid=33216 →` 经一次 bind 竞态重试后稳定为新监听进程）。
- 现 WebUI 由 supervisor(task `e56wrV`) 拥有，**替代**手动 LY0Gmt；后续启停一律走 `supervise.py`/`start_all.bat`。
- 三文件 `py_compile` 通过。

### 结论
「打开 WebUI 就报错」类复发从根上消除：服务常驻自愈，且即使用户手动杀掉也会自动恢复。

## 终极优化：多层自愈链（用户「终极优化」）
把可靠性做成可自愈的分层链：**登录自启 → run_guard.bat 外层 respawn → supervise.py → (ComfyUI+WebUI)**。
- **`supervise.py` 增强**：新增 `--status`（探一次打印表格，退出码 0=全 UP）/ `--once`；**日志按 5MB 轮转**（留 `.1`）；**自看门狗线程**（主循环 >300s 无心跳 → `os._exit(3)` 交外层重启）；其余（接管健康实例 / 回收非健康占用 / 假死重启 / 雪崩保护）不变。
- **`run_guard.bat`（新）**：外层 `:loop` 无限 respawn，supervisor 无论因何退出都 5s 后重拉（双保险）。
- **`status.bat`（新）**：双击即看两服务状态。
- **`register_autostart.bat` / `unregister_autostart.bat`（新）**：`schtasks /sc onlogon` 注册/移除登录自启（指向 run_guard.bat）。

### 验证（实测）
- `supervise.py --status` 正常：`ComfyUI :8188 UP pid=21116 / WebUI :8000 UP`。
- 重启 supervisor 加载新代码（`Stop-Process` 杀旧 → 后台起新），新 supervisor 重新接管：**WebUI pid 由 23496 → 21972**（父被杀的子树被回收 → 新 supervisor 重建），两服务探针均 200 —— 自愈链再次生效。
- ⚠️ **`schtasks.exe` 被沙箱安全策略拉黑**，`register_autostart.bat` 无法在沙箱内执行（报 `PROGRAM BLOCKED BY SECURITY POLICY`，且明令**不得重试/绕过**）→ **登录自启需用户手动双击 `register_autostart.bat`**（必要时管理员）。脚本本身已就绪。
- 结论：应用层自愈全自动化；唯一需用户手动的一步是跑一次 `register_autostart.bat` 开启开机自启。

## 新增功能：投稿元数据自动生成（用户「参照开源项目新增功能」）
- 发现真实缺口：B 站上传脚本用**硬编码** `TAGS`/`DESC` 常量，每集都一样、不可检索。
- 参照 **MoneyPrinterTurbo**（一句主题→自动标题/简介/标签）与 **ShortGPT**（auto title/description/hashtags），
  新增 `agent/metadata.py`：把 `series_script.json` 的某一集旁白喂给本地 LLM，产出
  **标题候选（3~5，含「第N集」）+ 简介（钩子+看点+话题）+ 标签 + 动态 + 英文标题**，
  一律经 `enforce_limits()` 收敛到 B 站约束（标题≤80 / 标签≤10 且单个≤20 / 动态≤233）。
  **无 LLM 也能用**：`rule_metadata()` 规则法兜底（确定性、可单测）。
- 接线：CLI `python cli.py metadata --ep N [--no-llm] [--preflight] [--json]`；
  WebUI `GET /api/metadata?ep=N`（**默认规则法即时返回**，`&llm=1` 才调模型，避免 LLM 超时阻塞请求）+ `services/metadata.py`。
- 需要同步的两处**冻结基线**：`tests/test_cli_registry.py`（expected 加 `metadata`）、
  `tests/test_webui_routes.py`（加 `("/api/metadata", ("GET",))`）—— 改动即改，否则 CI 红。
- 质量修正：规则法最初用 2-gram 词频抽标签，产出 `#自己/#知道` 这类垃圾词 → 改为
  `THEME_TAGS` 题材词库（记忆/芯片/霓虹/雨/门…）命中法，标签变干净（10 个全有意义）。
- 验证：`ruff check .` 全仓 **All checks passed**；`pytest -q` **430 passed**（原 424，+6 新用例）。

## 画质增强（参照 Video2X / Real-ESRGAN / MoneyPrinterTurbo）
- **发现的真实缺口**：项目原有三处 ffmpeg 编码（run_series crf18/medium、make_narration crf18/medium、
  anime_redraw crf17）**都没有 `-movflags +faststart`**。实测 `outputs/ep3_vo.mp4` 的 `moov` 在文件尾部
  → 网页播放必须整段下载完才能开始播；增强后 `moov@36` 前置 ✓。另缺 GOP/level/动漫 tune。
- **新增 `agent/encode.py`**（唯一权威编码档位）：4 档 `draft/standard/high/anime`
  （crf 23/18/16/16，preset veryfast/medium/slow/slow，tune -/-/film/**animation**）。
  动漫走 `tune animation` 是开源社区共识（保赛璐璐线条与平涂、抑制振铃）。
  统一带 `pix_fmt yuv420p` + `profile:v high` + `level:v`(>2048 宽或 >1080 高→5.1，否则 4.2)
  + `-g`(2s GOP) + `aac 192k/48k/2ch` + `+faststart`。`SR_MODELS` 按内容推荐超分权重
  （anime→`RealESRGAN_x4plus_anime_6B.pth`，real→`4x-UltraSharp.pth`）。
- **新增 `enhance_video.py`**：一键增强，**顺序固定 RIFE 插帧 → ESRGAN 超分 → 高质量重编码**。
  依据 Video2X 文档「高动态场景先插值再放大」—— 在低分辨率上补帧最省显存/时间。
  ComfyUI 不在则**自动降级为仅重编码**（`--strict` 才报错）；任一阶段失败保留已有成片，绝不毁片。
- **接入**：`cli.py enhance`（`--list-profiles/--kind/--sr-model/--no-rife/--no-sr/--denoise/--dry-run`）；
  `run_series.py --enhance <档位>` 或 `config.quality.enhance_profile`（CLI 优先），产物 `*_enhanced.mp4`。
- **顺带修**：`upscale_video.py` 的 `COMFY_INPUT` 不再写死 `D:/ComfyUI/input`
  （`COMFYUI_INPUT` env > `comfy_paths.comfyui_root()/input` > 旧字面兜底）。
- 验证：`ruff check .` 全仓过；`pytest -q` **446 passed**（435 + 11 新增）
