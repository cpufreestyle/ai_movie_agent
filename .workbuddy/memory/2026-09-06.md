## 排查「边缘模糊」→ 揪出 G 阶段静默失败（已修 3 个 bug）

用户反馈成片边缘模糊 + 要查日志。**WebUI 日志不落文件**，存在 `_state["logs"]` 内存里，要经 `http://127.0.0.1:8000/api/logs` 取（`Invoke-RestMethod .../api/logs`，看 `.logs` / `.result` / `.running`）。排查入口就是它。

### 真正的病灶：G 阶段根本没渲染，却报「全部完成」
`/api/logs` 显示：
```
=== G 阶段：LTX 渲染 18 镜并拼接 ===
[fatal] ComfyUI 不可达: ConnectionError
[abort] 第 1 镜失败
--- 完成：G 视频渲染        ← 失败也标记完成
=== 全自动流程全部完成 ===   ← 假成功
```
→ 后续 make_narration / H 封装拿 **9/3 的老 `ltx23_film.mp4`** 照跑，用户看到的是几天前的旧片，毫无感知。

三个 bug 串成一条链：
1. **端口漂移**：`run_ltx23_multishot.py` 硬编码 `URL=http://127.0.0.1:8200`，本机 ComfyUI 常驻 **8188** → 每镜 ConnectionError。
2. **假成功**：`main()` 失败时是 `return`（退出码仍 **0**）。上层 `webui.run_script()` 本来就查 `returncode`，但拿到 0 就当成功 → 照常往下跑。
3. **解说是英文**：LLM 生成的 `storyboard.json` 里 narration 是英文（`I stare at an old photo...`），覆盖了内置中文 → 中文 TTS 念英文 + 字幕英文。（画面里那行英文**就是 drawtext 烧的解说字幕**，不是模型生成的 LED 广告。）

### 修复（均已验证）
1. `run_ltx23_multishot.py` 加 `_detect_comfy_url()`：`COMFY_URL` 环境变量优先，否则依次探测 8188/8200/8189/8288，打印命中的端口。
2. 两个 multishot 脚本的 `main()` 所有失败路径返回 **1**，`__main__` 改 `sys.exit(main())`；`--concat`/`--shot` 分支同样返回码。
3. 解说语言校验：
   - `webui.storyboard_from_bible()` 加 `_zh_ratio()`，narration 中文占比 <0.3 即 **抛错中断**（宁可失败也不出英文片）。
   - `make_narration._apply_storyboard()` 同样校验：非中文段忽略，全非中文则**回退内置中文 9 段**。

### 验证结果
- 端口：`[comfy] 探测到 ComfyUI @ http://127.0.0.1:8188` ✅
- 退出码：`COMFY_URL` 指向 9999 时 `EXIT_CODE = 1` ✅（原先为 0）
- 中文回退：`[warn] storyboard.json 的解说全非中文，回退内置中文解说（9 段）` ✅
- 4 个改动文件 lint 0 错误。

### 待办
- **模糊问题未结案**：需修好后重跑一次出真新片再评估。若新片仍边缘偏软，两条路：①ffmpeg 加 `unsharp` 锐化后处理；②成片页切 LTX-2.5（画面锐度优于 2.3）。
