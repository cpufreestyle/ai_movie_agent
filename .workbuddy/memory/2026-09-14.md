## 白模 4 图渲染：两个假设被真机证伪（P2-⑨）
- **「用 View Layers 一次渲多文件」在 Blender 5.2 行不通**：多 View Layer 下 `write_still` 只写出**一个**文件（实测只得到 multi_.png）；合成器 File Output 路线能出多文件，但**渲染引擎是按场景生效的**，4 图塞进同一次渲染会让 line 需要的 CYCLES 把 depth/normal 也拖回去 → 净效果更慢。正确修法是修引擎泄漏，不是合并。
- **真正的浪费**：模板只在 line pass 前设一次 `engine="CYCLES"`，紧随其后的 depth/normal **没有任何回切**，两个纯 emission 材质的控制图一直白跑 CYCLES。
- 修法：`blender.fast_control_passes`（默认 true）→ depth/normal 回切 EEVEE；`blender.line_engine`（默认 cycles）。
- 实测 @1280x720/Blender 5.2.1：旧 9.92s → 新默认 6.63s → 再开 `line_engine=eevee` 1.24s（8x）。
- 逐像素校验（921600 px）：previs/line **完全相同**；depth 仅 0.08% 像素有差（99.87% 在边缘，内部 1 px）；normal 0.43%（99.75% 在边缘，内部 10 px）→ 差异只是轮廓抗锯齿。
- **EEVEE 在 5.2 能出 freestyle 线**（原注释「仅 CYCLES / legacy EEVEE 支持」不成立）：暗像素 0.84% vs Cycles 0.70%，线条掩膜 IoU 72.9%。Workbench 不能（且忽略材质节点 → depth/normal 材质法失效，差 55% 像素），排除。

## 本批踩到的坑（复用价值高）
- **并行 Edit 同一文件会互相覆盖**：本次在 `webserver/state.py` 上并行发多个 Edit，出现过 `import collections` / `_LogSink` / run_in_background 三处互相顶掉（报成功但内容没了）。改同一文件必须串行，改完 grep 复核。
