## 花屏根因 + 3D 动漫尝试（2026-09-12 凌晨）
- 用户看 `_preview_3dlow.mp4` 反馈"**画面花 + 多出一个人**"。
- ⚠️ **花屏根因 = prop 模式 VAE 反馈累积**：prop 每帧把【上一帧输出】再过 VAE 编解码，误差指数累积，~10 帧后散逸成彩虹噪点，并幻觉出额外人物。
  （代码里早有 warn 提示改用 keyframe。）→ **prop 模式不可用**，必须用 `--mode keyframe`（无反馈，不累积，彩噪≈源片）或 `--key 1` 逐帧重绘。
- 彩噪量化：极端彩噪像素占比（|a-128|>40 或 |b-128|>40 的像素比例）。prop 产物 28~30%（花屏），keyframe 产物 2.3~5.2%（干净，源片 6.84%）。
- 另一坑：**`--hires` 二次精修**在 1152×672 下 SD1.5 也易出彩噪 → 高危，慎用。
- **3D 动漫提示词的关键**：写实系 3D 词（`3d cgi render/octane/unreal engine 5/subsurface scattering`）会把脸渲染得**更像真人**→ 检出 **55~57%**（denoise 0.70 也压不住）。
  改成**卡通化 3D**（`stylized cartoon 3d, pixar cartoon, cel shaded, toon shading, big eyes, simplified features, non photorealistic` + NEG 强压 `photorealistic/real person/realistic skin`）
  → **检出 0/40 = 0%**，彩噪 5.22%。`anime_stable.py` 的 `STYLE3D_POS/NEG` 已按此调整。
- 当前最佳可交付组合：`--mode keyframe --key 8 --style3d --denoise 0.70`（无花屏 + 0% 检出 + 3D 卡通观感，待用户确认）。

## ⚠️【根因】花屏 = prop 模式逐帧传播发散（2026-09-12 定位）
- 现象：q1/q2/3d/sdxl 等样片出现**彩色噪点(花屏)**，用户强烈反馈。
- **逐帧相关性扫描**（各输出第 i 帧 vs 源片第 690+i 帧，128×128 灰度归一化互相关）：
  | 模式(40帧) | 相关性均值 | 坏帧(<0.3) |
  |---|---|---|
  | 朴素逐帧重绘 `anime_redraw.py` | 0.60 | **无** |
  | keyframe(关键帧+光流) | 0.57 | 2 帧轻微 |
  | **prop(逐帧传播+轻刷新)** | **0.14** | **第14帧起全坏** |
- **根因**：`prop` 每帧闭环「光流 warp → VAE编码 → 低 denoise 重刷 → VAE解码」反复迭代，
  **累积 VAE 编解码损失 + 光流误差**，约 10~14 帧后发散成噪点。**朴素逐帧重绘/关键帧模式不花屏**。
- **修复**：`anime_stable.py` 默认模式改回 `keyframe`；prop 分支加显式警告。**弃用 prop**。
- 副产物：`--mode keyframe --key 1` 等价于朴素逐帧重绘（复用 style3d/hires）。
- ⚠️ 3D 画风(`--style3d`)：`_preview_3dclean.mp4` 相关性 0.64 零坏帧(不花屏)，但**真人脸检出 70%**
  （3D/皮克斯提示词让脸更写实→RetinaFace 检出）。→ 3D 路线与"无真人脸"目标冲突，需更高 denoise 或真 3D 模型。
- 通用教训：**任何"把上一步输出当下一步输入"的迭代式流程，都会累积 VAE 损失**；img2img 应始终以**源帧**为 init。
- 用户报 `_preview_3dlow.mp4`（prop/denoise0.5/refresh0.15/48帧）**又花屏**（彩虹彩色噪点）。
- **根因（量化坐实）**：不是模型问题，是 **prop 逐帧光流传播的累积漂移**——每帧只做低 denoise 轻刷新，光流误差不被纠正，
  数十帧后发散成噪点。指标：亮度/色度高频。旧 3dlow 亮度高频 **135→829 单调飙升**；Counterfeit/SDXL 单帧测试(4帧)均正常。
- **修复**：`anime_stable.py` prop 模式新增 `--reanchor N`——每隔 N 帧用【源片】重新 img2img 一次，切断漂移累积。
  验证：`--reanchor 8` → 亮度高频 136~432 **有界**（不再飙升）。**长片 prop 必须开 --reanchor（建议 8~12）**。
- 用户已放弃 2D 动漫、改试 3D 动漫：`anime_stable.py` 加 `--style3d`（换 3D/CG 提示词预设 STYLE3D_POS/NEG）。
- 诊断工具：`outputs/_noise.py`（全片等间隔采样，输出亮度/色度 Laplacian 高频 + 饱和度，判花屏）。
  ⚠️ 本环境 `python -c` 多行会吞输出，且 `cv2.Laplacian` 需 CV_32F；改用脚本文件。
- 用户决定**放弃 2D 动漫，改试 3D 动漫(CG/皮克斯风)**。`anime_stable.py` 加 `--style3d`（换正/负向提示词：
