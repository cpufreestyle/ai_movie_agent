- **结论**：biliup 调用在 Windows + Clash/V2Ray 类代理环境下，必须显式设 HTTP_PROXY 环境变量。

## 修「无法新增文字 / 主题无法修改」UI 根因（2026-09-04）
- **真凶 = 轮询每秒覆盖文本框**：`pipeline.html` 的 `poll()` 每 1s 调用一次，代码 `if(!j.running&&j.result){...; loadPipeline()}`。服务器 `j.result` 在任务结束后**一直保留**，所以一旦空闲，`loadPipeline()` 每秒把所有文本框(bible/draft/prompt/image-prompts/主题)用服务器存档值覆盖 → 用户刚打的字 <1s 被清掉，表现为"无法新增文字""主题改不了"。
  - 修：增加 `_wasRunning` 标志，只在「运行中→空闲」那一次跳变时 `loadPipeline()` 一次（`const justFinished=_wasRunning&&!j.running; _wasRunning=j.running; if(justFinished&&j.result){...}`）。

  - 验证：接口写入→读回→恢复原 4 条均正常。
- 注意：`pipeline.html` 是浏览器缓存，改完需 **Ctrl+F5** 强刷才生效；`webui.py` 改动需重启 flask 进程。
- G 阶段日志里 `=== G 阶段完成 ===` 是「生成视频提示词」(只生成文本 prompt) 的正常返回；真正出视频的「使用 SkyReels 生成视频」按钮在本机 SkyReels 未装时 `disabled`。日志里多次 `已请求停止` 是用户连点停止，且为"阻塞任务本轮结束后才生效"。

- **现象**：C 概念企划、桥接分镜均 `[llm] 调用失败: Error code: 502`，最终 `LLM 返回为空`。
- **根因两根**：
  1. **502 是 Ollama 瞬时错误**（冷加载/并发大请求时偶发 Bad Gateway）。直连 Ollama `/api/chat` 测 3 个模型全部 200 无 502，证明不是模型问题。
  2. **`gemma4:e2b` 是推理模型**：Ollama 把回答放进 `thinking` 字段、`content` 常为空（小 `max_tokens` 时全去 thinking → 正文空）。这正是"LLM 返回为空"的直接原因。
- **模型对比实测**（长提示+num_predict）：`gemma4:e2b`(推理,content 需大 max_tokens 才有)、`llama3:latest`(非推理但输出英文)、`qwen2.5:3b`(**非推理+中文+7s 最稳**)、`qwen3.5:9b`(Qwen3 推理有 risk)。已装模型见 `ollama list`。
- **改动**：
  1. `config.yaml`：`llm.model` 与 `profiles.llm.ollama_lfm.model` 由 `gemma4:e2b` → **`qwen2.5:3b`**。
  2. `agent/llmutil.py` `_OllamaClient._create`：① 加重试 3 次(2s 退避)抗瞬时 502；② `content` 为空且 `thinking` 有值时**回退取 thinking** 作正文（兼容推理模型）。`import time` 已加。
- **关键坑：webui 缓存 agent**。`get_agent()` 首次构造后缓存在 `_state["agent"]`，各组件(Writer/Planner/...)在构造时把 `model` 固化进客户端。**只改 config.yaml 不重启 webui 不会生效**——必须杀掉旧 flask 进程再重启，agent 才会用新 model 重建。已杀 49780、重启新进程 17728，验证 `/api/config` 的 `llm.model=qwen2.5:3b`、`/api/overview` 的 `agent_error=None`。
- 用户可在 webui 重跑企划/分镜任务验证。如想要更高质量可换非推理中文大模型（注意别用 Qwen3/gemma4 类推理模型，否则需靠 thinking 回退）。
