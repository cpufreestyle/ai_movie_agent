## 【推翻上一节】SageAttention2/3 在 Win+sm_120 实测跑通（2026-09-10 晚）
- **纠正**：上文「attention 后端排查」判定「Windows+sm_120 上 SDPA 是唯一可用后端、triton 无解」**是错的**。当晚成功装上并实测 SA2/SA3。
- 两个卡点的正确解法：
  1. **triton**：PyPI 官方 triton 不支持 Windows，但社区版 **`triton-windows`** 支持，`pip install triton-windows` 装到 3.8.0（cp313），torch 未被覆盖。
  2. **wheel**：别碰 PyPI（`sageattention` 1.0.6 版本老旧且依赖缺失）。用 HF **`ussoewwin/Sage-Attention-for-Windows`**，含 SA2/SA3 各版本的 cp312/313/314 × cu130/cu132 × torch2.10~2.14 预编译 wheel。本机的完美匹配：
     - `sageattention-2.2.0+cu130torch2.11.0-cp313-cp313-win_amd64.whl`（SA2, 25MB）
     - `sageattn3-1.0.0+cu130torch2.11.0-cp313-cp313-win_amd64.whl`（SA3, 4.1MB）
  3. 安装必须 `--no-deps`（防 pip 覆盖 torch 2.11）；wheel 文件名**必须保留完整五段标签**，重命名为 `sageattn3.whl` 会报 `Invalid wheel filename`。
- 基准 `_bench_sage.py`（bf16, H=12, D=128, 对比 SDPA）：

  | L | sdpa | sa2 | sa3 |
  |---|---|---|---|
  | 512 | 0.07ms | 0.19ms (0.35x 慢) | 0.27ms (0.24x 慢) |
  | 2048 | 0.78ms | 0.18ms (**4.28x**, cos .9993) | 0.28ms (**2.79x**, cos .9823) |
  | 8192 | 10.93ms | 1.76ms (**6.22x**, cos .9992) | 1.55ms (**7.05x**, cos .9812) |

- 结论：① **短序列(L≤512) 别用 Sage，反而慢 3~4 倍**（量化开销 > 带宽收益），交叉点在 512~2048；② SA2 cos≈0.999 几乎无损、SA3 cos≈0.981 有可见量化损失（FP4 代价，与上游 README ~0.98 吻合）；③ SA3 仅在长序列略快于 SA2（7.05x vs 6.22x），但精度差一档。
- **对 H3 的取舍**：用户极在意人脸一致性，SA3 那 2% attention 误差很可能优先劣化人脸 → 优先选 SA2（几乎无损 6x），SA3 仅作极限提速备选。
- ComfyUI 启用机制（`comfy/ldm/modules/attention.py`）：
  - `--use-sage-attention` 启动参数 → `optimized_attention = attention_sage` = **SA2 全局生效**（第 855-857 行），H3 走标准 `optimized_attention`/`attn1_patch` 接口，能直接吃到。
  - SA3 是 `register_attention_function("sage3", attention3_sage)`（第 891-892 行）**注册式、按节点选**，不是全局参数 → 需要 KJNodes 的 `PatchSageAttentionKJ`（**本机未装 KJNodes**）或等效 patch 节点才能切。
- 启动脚本 `_launch_comfy.py` 当前 args 仅 `--port 8188`，加 `--use-sage-attention` 即可启用 SA2。

## 【重要】解锁「锚定+多参考图」：修复 task 判定漏算 ref_images（2026-09-10）

- **H3 task 合法组合**（conditioning.py:316-337）：`hybrid=(None,None,True)`，即 **refs 可以是 ref_images，不强制 ref_video**；hybrid 只要求 `has_refs` 且 `first or last`。所以「锚定首帧 + 多张 Mira 参考图」本就合法。
- 修复：`has_refimg` 把 ref_images 计入 → `has_any_ref`，image+ref_images 正确走 **Hybrid**。**无需白模 ref_video**，规避了「参考视频运动信号压过身份」的老问题。

  | +ref_images(4张) / **39帧** | **0.2769** | 0.219 | **8/8** |
